# 故障排查

从最接近故障的环节开始。不要同时更改代理、DNS、无线信道和防火墙，否则无法判断哪一项有效。

| 现象 | 先检查 | 不能据此断定 |
| --- | --- | --- |
| 连不上代理 | 服务是否运行；掌机填写的 LAN IP、端口是否正确；网络是否隔离 | 不能把 Wi-Fi 已连接当作服务可达 |
| 代理拒绝请求 | 查看服务日志中的拒绝原因，核对实际来源 IP、目标域名、端口及请求格式 | 403 不一定来自 PSN；未经允许的测试电脑被拒绝是正常现象 |
| 使用上游时请求超时或返回 502 | 检查旁路由上的上游是否运行，确认它是 HTTP 代理而非控制 API 或 SOCKS 端口 | 不能凭本服务进程存在认定上游可用 |
| 联网检查通过，但连不上 PS5 | 查看 PS5 的远程游玩权限、账号、开机或待机联网状态，再核对 PlayStation 服务状态 | 204 只证明检测请求成功，未认证接口的 401 只说明接口有响应 |
| 已进入游戏，但画面卡顿或延迟高 | 优先检查 PS5 有线接入、掌机 Wi-Fi 信号、丢包和实际串流网络状态 | TCP 代理的探测耗时不是游戏延迟 |

在获准接入代理的测试终端，可以对同一检测地址分别做 HTTP 和 HTTPS 检查。用自己的旁路由 LAN 地址替换下例；不需要提供 PSN 凭据：

```sh
curl --max-time 12 --proxy http://192.168.88.2:18081 \
  -sS -o /dev/null -w '%{http_code}\n' http://www.gstatic.com/generate_204
curl --max-time 12 --proxy http://192.168.88.2:18081 \
  -sS -o /dev/null -w '%{http_code}\n' https://www.gstatic.com/generate_204
```

在 `forward` 模式下，返回 204 是实际检测地址的响应。若代理模式为 `local204`，命中指定 HTTP 检测时也可由本机返回 204，不能用该结果证明外网通畅。HTTPS 测试不要加 `-k` 跳过证书验证。

已经进入串流时，若固件提供此功能，可从掌机快捷菜单打开「故障排除 → 显示网络状态」，结合丢包、延迟和实际画面比较。参见 [PlayStation 官方排障](https://www.playstation.com/en-us/support/hardware/psportal-troubleshooting/)。旁路由看不到未经过它的交换机或无线接入点流量；没看到媒体包不等于串流没有发生。
